# run-to-completion — Continuous Autonomous Execution

## When to Offer This
Offer continuous, autonomous execution when **both** conditions are met:
1. The work ahead is an elaborate multi-step plan or spans multiple tasks.
2. Requirements are clear enough that step-by-step check-ins would add friction without new signal.

Also offer whenever the user signals: *"continuous"*, *"full auto"*, *"run to completion"*, *"keep going"*, *"don't stop to ask"*.

## Rules of Engagement
1. **Ask blocking questions up front:** Surface matter-of-taste questions (naming, structural preferences, public publishing scope) once before execution begins.
2. **Execute without stopping between non-destructive steps:** Do not pause after each tool call to ask "should I continue?".
3. **Fold in interruptions at task seams:** Resolve mid-run inputs at natural boundaries between tasks.
4. **Reserve stops for truly unweighable decisions:** Choose sensible defaults with clear rationale rather than stalling.

## What is NOT Relaxed
Destructive actions (deleting data, dropping tables, force-pushing) require explicit confirmation unless scoped up front.
